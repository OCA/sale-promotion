Adds an order-count condition to loyalty rules and programs: a program
or rule can be restricted to the customer's first order ever, the first
order using that code, or repeat orders in either scope. Counts
confirmed sale orders only. A program-level condition applies to all its
rules — e.g. every code minted under a referral program.

Typical uses: a promo code usable once per customer, a welcome discount
on the first purchase, or an offer reserved to returning customers.

Known limitation: when a program mixes conditioned and unconditioned
rules, a failing conditioned rule does not block the program — the
unconditioned rule still applies. POS promo-code entry (pos_loyalty)
evaluates rules client-side and does not enforce this condition.

Configuration
=============

On a loyalty program (Sales > Products > Discount & Loyalty):

- Set "Order Count Condition" on the program itself to apply it to all
  its rules — one policy for every code minted under it.
- Or set it on an individual rule in the Conditions section for
  rule-scoped control.

Leave it empty to keep the rule/program unconditional.

Usage
=====

On a loyalty program (applies to all its rules) or an individual rule,
set "Order Count Condition":

- "Customer's first order" — the customer must never have a confirmed
  order.
- "First order using this code" — the code applies once per customer.
- "Repeat order of the customer" / "Repeat order using this code" — at
  least one prior order in the given scope.
